## P2.1 —— 泛化布局（可选，排在 LLM 之后）

### 现在被拒绝的，是"没验过"而不是"做不到"

```json
{"code": "LAYOUT_UNSUPPORTED",
 "message": "网络 'in' 有 2 个到地元件（R1, R2），是并联到地",
 "hint": "P2 每一级最多一个到地元件。两个元件并联到地（比如电阻和电容并联）还没验证过；拆成一个元件，或先用两个电路分别验。",
 "context": {"reason": "parallel_shunt", "net": "in", "shunts": ["R1", "R2"]}}
```

`fork` / `parallel_shunt` 这两类现在是明确拒绝。**网表照样成立**（坐标不影响
连通性），真正没做的是两件事：

1. 两条并排支路怎么摆才看得懂；
2. 怎么保证导线不穿过别的符号框 —— v0.7.0 已经踩过一次
   （`docs/layout.md` 第 6 节），泛化之后约束只会更多。

### 为什么排在 LLM 之后

`ladder` 已经覆盖滤波器 / 分压 / T 型 / 衰减器这一大类教学电路。
LLM 接入的收益远大于再支持一种并联摆法。

## P3 —— 元件库扩容

### 问题

现在只能克隆"样例库里出现过"的 `(family, part)`。多引脚元件（运放、555）
的引脚重映射还没验证过，`add_part` 目前只对 2 引脚 + 地做过验收。

### 方向

1. 从 `corpus/samples_index.json` 挑一个运放样例，跑通 `add_part` 的多引脚路径
   （重点：`PortID` 重映射、引脚名是否唯一）。
2. 建 `templates/` 目录，把每种用到的元件子树存成模板，摆脱"必须找到 donor 文件"。
3. 单位哈希表：`&UNI<值>_uc<hash>` 的 hash 算法未知，现在是"继承旧值后缀"绕过的。
4. 探针 > 9：`LocalName` 序号超过一位数字时的命名规则需要先确认。

## P4 —— LLM 外壳（现在就是下一步）

现在有**两条**入口，都产出同一份 Circuit IR：

```
自由中文 ──► nl2ir ──┐
                     ├──► Circuit IR ──► msbuild ──► .ms14 ──► Multisim
Agent ──► MCP ───────┘
```

LLM 的正确位置是**最上面**，且只做"规范化"：

```
自由中文
  ↓  LLM：只把口语说法规范化成受控句式，不产出 IR
受控句式（"1V 1kHz 正弦源，经过 1kΩ 电阻后接 159nF 电容到地，..."）
  ↓  nl2ir（确定性、可测试）
Circuit IR
```

失败时把 `NLParseError.issues` 或 MCP 的 `error.hint` 回灌给模型让它重写。
**不要让 LLM 直接写 IR**，否则"同一句话两次生成不同电路"会一直跟着你。

### 第一个测试已经跑过了（没有 LLM，纯 Agent）

> **"创建一个 1V、1kHz 的正弦输入，设计一个截止频率约为 500Hz 的一阶 RC 低通滤波器。"
> —— v0.6.1，13 次调用零错误，误差 −0.577%**
>
> **"设计一个 1kHz 正弦输入经过二阶低通滤波器，截止频率约 2kHz，输出幅值与理论值验证。"
> —— v0.7.0，19 次调用零错误，增益误差 −0.219%、相位误差 −0.123°**

两次都是**外部 Agent 只读 `tools/list`**，自己选拓扑、自己选器件、
自己算理论、自己判断误差。也就是说"Agent 能不能用 MCP"这件事已经验证完了。

所以接 LLM 时要验的不再是能力，而是**三件事**：

1. LLM 能不能在只看 `tools/list` 的情况下**稳定地**选对工具和参数
   （同一个需求跑 10 次，看有几次零错误）；
2. 出错时能不能只靠 `error.hint` + `context` 自己改回来；
3. 它会不会为了"让结果好看"去改电路参数 —— 这是最需要防的。
