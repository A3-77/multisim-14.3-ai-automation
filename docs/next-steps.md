## P2.1 —— 泛化布局（一半做完了，v0.10.0）

### 已经放开的：同一节点 2 个到地元件

`parallel_shunt` 从"明确拒绝"变成支持（v0.10.0）。这一条覆盖的是教学电路里
出现频率最高的一类形状：

| 电路 | 形状 | 说明 |
| --- | --- | --- |
| 分压 + 旁路电容 | 1 串联 + (R ∥ C) 到地 | 静态工作点 + 交流旁路 |
| RC 并联负载 | 1 串联 + (R ∥ C) 到地 | 增益 0.4472 ∠ −26.57°（验收电路） |
| 电阻并联 | 0 串联 + 2 个 R 到地 | 等效电阻 |

几何上只做了一件事：第 2 个到地元件在同一行往右挪半格（`SHUNT_DX = DX/2`），
单个到地元件的坐标**一个字节都没变**（有回归测试守着）。

### 还没放开的：`fork`（一个节点两条向下的主干）

```json
{"code": "LAYOUT_UNSUPPORTED",
 "message": "网络 'in' 有 2 条向下的主干（R1, R3）",
 "hint": "P2 支持『单主干 + 到地并联』：一个节点只能有一条向下的主干。两条并排的支路（比如两组 RC 并联）还没验证过。",
 "context": {"reason": "fork", "net": "in", "branches": ["R1", "R3"]}}
```

`fork` 和 `parallel_shunt` 有本质区别：后者是"一个节点往下挂了几个元件"，
前者是"一个节点分出几棵子树"。网表照样成立（坐标不影响连通性），真正没做的
是**子树怎么摆** —— 每一棵子树自己又要满足"不穿符号、层级看得懂"，
这是递归的布局问题，不是加一个偏移量能解决的。

### 为什么 `fork` 排在后面

`ladder` + `parallel_shunt` 已经覆盖滤波器 / 分压 / T 型 / 衰减器 / 旁路这一大类。
`fork` 的典型代表是"两组 RC 并联后接同一个节点"，在教学中远不如前者常见。

## P3 —— 元件库扩容

### 问题

现在只能克隆"样例库里出现过"的 `(family, part)`。多引脚元件（运放、555）
的引脚重映射还没验证过，`add_part` 目前只对 2 引脚 + 地做过验收。

### 方向

1. 从 `corpus/samples_index.json` 挑一个运放样例，跑通 `add_part` 的多引脚路径
   （重点：`PortID` 重映射、引脚名是否唯一）。
2. 建 `templates/` 目录，把每种用到的元件子树存成模板，摆脱"必须找到 donor 文件"。
3. 单位哈希表：`&UNI<值>_uc<hash>` 的 hash 算法未知，现在是"继承旧值后缀"绕过的。
4. 探针 > 9：`LocalName` 序号超过一位数字时的命名规则需要先确认。

## P4 —— LLM 外壳（v0.8.0 已完成，但只做了一半）

现在有**两条**入口，都产出同一份 Circuit IR：

```
自由中文 ──► nl2ir ──┐
                     ├──► Circuit IR ──► msbuild ──► .ms14 ──► Multisim
Agent ──► MCP ───────┘
```

v0.8.0 走的是**右边那条**：LLM 直接当 MCP 的使用者，自己设计电路、自己调工具。
它没有走 `nl2ir` —— 也没有必要走：`nl2ir` 只认受控句式，而 LLM 已经能直接产出
正确的工具调用序列。`nl2ir` 现在的价值是"确定性、可单测、零 LLM 成本"的离线路径。

### v0.8.0 已经验证的三件事

| 原来要验的 | 结果 |
| --- | --- |
| 只看 `tools/list` 能不能稳定选对工具和参数 | ✅ 5 个任务 128 次调用，只有 3 次报错，全部一次自愈 |
| 出错能不能只靠 `hint` + `context` 改回来 | ✅ `MISSING_PARAMETER` / `PROBE_NOT_FOUND` 各一次，改法都能在 `hint` 里找到 |
| 会不会为了让结果好看去改参数 | ✅ 阶段三 Agent 在报错后**一字未改原电路**，另建子电路做分解验证 |

### 还没验的（下一轮真正要做的）

1. **稳定性**：同一个需求跑 10 次，看有几次零错误。本次每个任务只跑了一次，
   样本量不足以说"稳定"。
2. **长上下文**：一个会话里连做 5 个电路、隔 30 轮再回来改第 2 个 —— `get_circuit`
   和 `circuit_id` 到底够不够用，现在只有阶段三的 4 电路切换算一次小样本。
3. **对抗性**：给一个物理上不可能的需求（比如"用 1 个电阻做二阶低通"），
   看它是老实说做不到，还是硬凑一个能跑但错的电路。
4. **成本**：128 次调用里 11 次是真机仿真（20~30 s/次），实际墙钟约 6 分钟。
   要产品化，得先解决"每次 `simulate` 都重启 Multisim"的开销。
