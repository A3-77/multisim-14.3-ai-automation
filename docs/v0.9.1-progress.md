### 1.4 一个必须如实报告的老问题：符号不渲染

- `docs/README` 里 v0.8 就记过：「`GetCircuitImage` 对我们生成的 `.ms14`
  画不出 V1/C1 符号」。这次复核：**问题比记录的更严重** ——
  在真实 GUI 里，V1 / R1 / GND1 的符号也画不出来，只有导线、探针框、
  以及个别元件（D1 二极管）能看见，而且 D1 还偏在导线之外。
- 已排除的原因：
  - 不是"坐标没跟着平移"：同一电路放到 x=500 / x=300 两次编译，
    符号本体、文字、引脚三者**平移量完全一致**（各差 200）。
  - 不是"Multisim 另存会修正"：`save_as` 之后所有 `Transformer-M20/M21`
    一个字节都没变。
  - 不是"串档"：打开第二个文档会直接段错误（32 位 COM 限制），
    所以每次渲染的对象就是当前文件。
- 结论：这是 `.ms14` 里符号几何数据本身的问题（donor 克隆时
  `CIITSymbolComp` 的变换与绘图子对象的变换语义不一致），
  **不影响网表与仿真**，但影响"给人看"。列为 v0.9.1 的已知缺陷，
  不阻塞验收，但必须在报告里明确写出来。

> **✅ 已于 v0.9.1 修复**：上面的判断方向对了，但归因不准。
> 真正的根因是 `Assembler.add()` 平移时把 **symbol 根节点**的
> `Transformer-M20/M21` 也加了偏移，而 Multisim 渲染时会再把根变换叠加
> 到子对象（子对象存的是图纸绝对坐标）→ 符号被推出画布。
> 根归零后 V1/R1/C1/GND/D1 符号全部正确对位，电气行为零变化。
> 完整证据见 `docs/v0.9.1-symbol-fix.md`。

- 打开 GUI、关弹窗、最大化、顶前台 → OK
- 点菜单进 Analyses 对话框 → OK（菜单偏移实测标定为 rect 原点 +(249, 43)，

  （原来用鼠标点行，125% DPI 下会点偏一行，实测点成了「直流扫描」，
  出来的是 DC 传输特性而不是瞬态波形）
- TSTOP/TMAX 写入 → **OK，可回读校验**。两个坑：
  ① 同一控件 ID 在对话框里有多个实例（交互式面板那份隐藏、值是 `1e+30`），
     必须挑 `IsWindowVisible` 为真的那个，否则写进去静默无效；
  ② `WM_GETTEXTLENGTH` 是 `0x000E`、`WM_GETTEXT` 是 `0x000D`，
     之前把两者搞反，误判成"写不进去"。
- 点 Run、等「图示仪视图」、PrintWindow 抓图 → OK
- 图示仪**不要最大化**：绘图区会填满客户区，横轴刻度标签被下沿切掉；
  自然尺寸（约 658×470）反而能完整露出时间轴。
