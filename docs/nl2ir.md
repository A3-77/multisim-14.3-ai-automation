# 自然语言 -> Circuit IR（v0.4.0）

> 这一层只做一件事：**把一句中文变成 Circuit IR**。
> 不碰 XML、不碰 `.ms14`、不碰 Multisim —— 那些是 `ir_compile` 和 `msbuild` 的活。

```
中文描述
  ↓  nl2ir.parse()          ← 本文件
Circuit IR（纯 JSON）
  ↓  CircuitIR.validate()
  ↓  ir_compile
.ms14
  ↓  Multisim + COM
波形 → 拟合 → 与理论比对
```

---

## 1. 为什么是规则解析器，不是 LLM

因为这一层必须**可复现**。同一句话，今天和下周必须解析成同一份 IR，否则
下游 `.ms14` 和仿真结果就没有可比性，"回归测试"这个词也就失去意义。

规则解析器的另外两个好处：

- 解析失败时能精确说清缺什么（"正弦源没给频率"），LLM 往往会自己补一个。
- 零依赖、零网络、毫秒级，可以当单元测试天天跑。

LLM 的正确位置在**更上层**：把自由表述规范化成受控句式，再交给这里。
本项目不做这一步（见第 7 节）。

## 2. 支持的句式

### 元件

| 写法 | 例子 |
| --- | --- |
| 值在前 | `1kΩ 电阻`、`159nF 电容`、`1V 1kHz 正弦源` |
| 值在后 | `电阻 1kΩ`、`电容 159nF`、`正弦源 1V 1kHz` |
| 带位号 | `电阻 R1 = 1kΩ`、`正弦源 V1 = 1V，频率 1kHz` |
| 中文单位 | `1 千欧`、`159 纳法`、`1 千赫`、`100 毫伏`、`6 毫秒` |
| 地 | `接地`、`到地`、`GND` |

### 拓扑

只支持一种：**串联链 + 末端接地**。顺序 = 元件在句子里出现的顺序。

```
"经过 1kΩ 电阻后接 159nF 电容到地"
   → V1.+ → R1 → C1 → 地
```

`并联` 会明确报错，不会硬凑一个拓扑出来。

### 探针

| 写法 | 结果 |
| --- | --- |
| `在输出节点放一个电压探针` | 1 个探针，落在 `out` |
| `在输入节点和输出节点各放一个电压探针` | 2 个探针，`in` + `out` |
| `在 R1 两端放电压探针` | 2 个探针，落在 R1 两侧的网络 |

网络命名：首网 `in`，末网 `0`（地），最后一个无源元件**之前**那个网叫 `out`，
其余 `n1`、`n2`。

### 仿真

| 写法 | 结果 |
| --- | --- |
| `做瞬态分析` | `analysis = transient`（默认就是它） |
| `仿真 6ms` | `stop = 0.006` |
| `仿真 3 个周期` | `stop = 3 / f` |
| 不写 | `stop = 6 / f`（6 个周期） |
| `采样率 200kHz` | `sample_rate = 200000` |
| 不写 | `sample_rate = 200 × f`（每周期 200 点） |

默认值不是随手定的：6 个周期足够跳过起始暂态，200 点/周期足够让最小二乘
拟合的幅值误差进到 0.1% 量级。

`交流分析` / `扫频` / `直流工作点` 会明确报"暂未接入"，因为 COM 侧那几条取数
路径还没验证过。

## 3. 解析算法

四步，全在 `tools/nl2ir.py` 里：

**① 归一化**
全角转半角；中文单位换成符号（`千欧`→`kΩ`、`纳法`→`nF`、`μ`→`u`）。
长词优先，否则 `千欧` 会被 `欧` 先吃掉。

**② 摘出"已经被消费"的片段并打码**
仿真参数（`仿真 6ms`、`采样率 200kHz`）和探针短语先抽出来，
原文对应位置换成等长空格。这一步是必须的：

- `采样率 200kHz` 里的 `200kHz` 会被当成信号频率；
- `在电阻两端放探针` 里的 `电阻` 会被当成第二个电阻元件（还没值 → 报错）。

打码用等长空格，字符位置不变，后面的正则照常工作。

**③ 类型词 + 数值，按"连续短语"归属**

类型词（`电阻`/`电容`/`正弦源`/`电源`/`地`…）和数值（`1kΩ`/`159nF`/`1V`/`1kHz`）
各自扫一遍，然后决定"这个数值属于哪个元件"。

规则是**连续的一段**，不是"最近的几个"：

```
"1V、1kHz 正弦源"          两个数值都归正弦源（顿号不断开）
"1kΩ 电阻后接 159nF 电容"  1kΩ 只归电阻（"后接"是分界，159nF 归电容）
"1V 1kHz 正弦源和 2V 2kHz 正弦源"
                          第一个源拿 1V/1kHz，第二个拿 2V/2kHz
```

实现是"从类型词向两侧走，只要中间间隔还是空白/顿号/逗号/等号/`的`/参数标签/位号，
就继续收；一旦碰到连接词（接、连、串、经、和、与）或另一个类型词就停"。

为什么不用"最近距离"：`电阻、1kΩ 电阻` 这种并列写法里，两个 `1kΩ` 到两个
`电阻` 的距离完全对称，最近距离会随机挑一个，把两个值都塞给前一个电阻。
连续短语没有这个歧义。

**④ 建链、建网、放探针**

```
chain = [源] + 无源元件（按文本顺序）
nets  = [in] + 中间网 + [0]
```

引脚约定：无源元件 `1` 是入口、`2` 是出口；源的 `+`/`-` 是 IR 层别名，
编译时由 `ir_compile` 翻成真实引脚名 `1`/`2`。

布局复用 `tools/build_rc_lowpass.py` 里**实测通过**的那组坐标
（源 300,300 → 第一个无源 500,300 → 后续 700,400 → 地 300,420）。
坐标含义是引脚质心，不是符号锚点。

## 4. 错误哲学：不猜

缺频率、缺阻值、拓扑不支持、元件不在白名单 —— 一律抛 `NLParseError`，
一条一行说清缺什么、该怎么改：

```
解析失败：
  - 正弦源 '正弦源' 没给频率（例：'1V 1kHz 正弦源'）
  - 电容 '电容' 没给容值（例：'159nF 电容'）
  - 串联链里有 3 个无源元件，超过已验证上限 2 个
```

为什么这么严：猜错一个值，电路照样能生成、照样能跑仿真，**但结论是错的**。
"看起来能跑"比"直接报错"危险得多 —— 这正是本项目 v0.1.0 阶段踩过的坑
（克隆的电阻被误判为开路，实际是 `SimState` 被压平）。

同理，`把 R1 改成 2kΩ` 这种"修改已有电路"的句子会被直接拒绝：
本层只从零新建。

## 5. 边界：IR 里不能出现 Multisim 概念

`nl2ir` 产出的 JSON 里没有 `CiID` / `CiPort` / `CIITSymbolComp` / `CiaParamList`，
只有"有哪些元件、谁和谁连、探针放哪、怎么仿真"。

这条边界是项目能不能长大的关键。用户说的是
"帮我画一个 1V 1kHz 的 RC 低通"，不是
"创建一个 CIITSymbolComp 并设置 M20/M21"。

## 6. 验收（实测，非推断）

一句话：

> 创建一个 1V、1kHz 的正弦源，经过 1kΩ 电阻后接一个 159nF 电容到地，
> 在输入节点和输出节点各放一个电压探针，然后做瞬态分析。

结果（`tools/nl_run.py`，32 位 Python + Multisim 14.3 实跑）：

| 检查项 | 结果 |
| --- | --- |
| 中文 → IR | 4 元件 / 3 网络 / 2 探针，`validate()` 无错 |
| 与 `examples/rc_lowpass.ir.json` 对比 | 语义**完全一致**（字段逐个相等） |
| IR → `.ms14` | 31754 字节 |
| Multisim 打开并注册探针 | `['V(探针1)', 'V(探针2)']` |
| 输入幅值（声明 1 V） | 0.99679 |
| 增益 | **0.70632** / 理论 0.70745 |
| 相位 | **−45.06°** / 理论 −44.97° |
| 与直接 `add_part` 基线对比 | 增益 Δ=0.00e+00，相位 Δ=0.000° |

最后一行是重点：**中文链路和手写 API 链路给出逐位相同的答案**，
说明这一层没有引入任何偏差。

第二句（换元件、换频率、换量级，验证不是写死一句话）：

> 100mV、2kHz 的正弦信号源，经过 2.2kΩ 电阻后接 100nF 电容到地，
> 在输入和输出各放一个电压探针，仿真 6ms，采样率 200kHz。

`fc = 723 Hz`，2 kHz 处理论增益 0.340 —— 实测值与理论值的对照见
`out/nl/nl_V1_R1_C1_2000Hz.result.json`。

纯解析层的测试（不需要 Multisim，46 项）：

```bash
python tools/test_nl2ir.py
```

## 7. 明确不做（这一版）

| 不做 | 原因 |
| --- | --- |
| 直流源（`DC_POWER`） | 不在 IR 白名单。且纯电阻回路没有动态元件，瞬态会立刻结束、探针注册不上（v0.1.0 踩过，`build_acceptance.py` 头注释有记录） |
| 并联 / 多支路 | 布局和连线没验证过，硬做出来只会是"能生成但不能仿真" |
| 串联链 > 2 个无源元件 | 只实测过 1~2 个元件的坐标组合 |
| 电感 / 二极管 / 运放 / 555 | 不在 IR 白名单，`add_part` 的多引脚元件支持还没验证 |
| LLM 自然语言理解 | 规则层先稳定下来；LLM 应该只负责把自由表述规范化成受控句式 |
| 探针 > 9 个 | `LocalName` 序号超过一位数字时的命名规则未确认 |

## 8. 下一步

1. **直流源 + 静态电路取数**：先解决"纯电阻回路探针注册不上"，
   才谈得上支持原始验收句"5V 直流电源串联 1kΩ 电阻接地"。
2. **并联拓扑**：需要先解决布局（结点对象是否真的不需要，v0.2.0 已证伪过
   "必须有 junction"）。
3. **LLM 外壳**：输入自由中文 → 受控句式 → `nl2ir`。失败时把 `NLParseError`
   的 issues 回灌给模型让它重写，而不是让它直接产出 IR。
