### 2.1 ComponentSpec：一个字段都不是手写的

`build_registry.py` 扫 `corpus/samples14`（10 个 .ms14）+ Multisim 官方样例（118 个），
对每个 `(family, part)` 抽出：

```json
"DIODE/1N4007G": {
  "pins": ["A", "K"],                              // 引脚顺序（符号定义顺序）
  "pin_geometry": {"A": [279,297], "K": [279,243]}, // 引脚几何（donor 坐标）
  "pin_extent": [0, 54], "orientation": "vertical", // 竖直符号，A 在下
  "spice_template": "d%p %tA %tK %m",               // 按引脚名引用
  "n_params": 0,                                    // 参数槽 0 个 → 不接受 value
  "refdes_prefix": "D",                             // 从 donor 位号 D2 推出来
  "donor": {"file": "corpus/samples14/Fuente capacitiva final.ms14",
            "refdes": "D2", "in_repo": true},
  "n_donors": 2
}
```

三个细节值得记：

1. **SPICE 模板原文带 `@@WB_NL@@`**（Multisim 的换行控制符），直接存会污染下游解析。已剥掉。
2. **donor 在仓库里**（`Fuente capacitiva final.ms14` 的 D2），不依赖 Multisim 安装目录。
   换台机器只要有这个 corpus 文件就能编译。
3. **`n_params = 0` 正好解释了"二极管为什么不需要 value"** —— 型号决定一切，
   这个结论是推出来的，不是猜的。

目录里 192 种，`enabled` 只有 1 种。**"扫到过"和"已支持"在数据结构上就是两个字段**，
不靠文档提醒。

> 顺带一个账目更正：上一轮报 donor 池 193 种，本轮 `build_registry` 报 **192**。
> 差 1 的原因没追（两次统计的过滤条件不同：本轮会丢掉 family / part / 位号任一为空的条目）。
> 不影响结论，但记下来免得以后对不上账。

### 2.2 MCP 层：Agent 不再被白名单挡住

`circuit_ir.py` 拆成两段，界线是"谁保证它是对的"：

```python
LEGACY_SUPPORTED = { ... 5 条手写字面量，v0.1~v0.8 真机验过 ... }
REGISTRY_SUPPORTED = {}      # 从 registry.enabled 读
SUPPORTED = dict(LEGACY_SUPPORTED); SUPPORTED.update(REGISTRY_SUPPORTED)
```

registry 的条目**不会覆盖** legacy（`if key in LEGACY_SUPPORTED: continue`），
并留下 `REGISTRY_LOAD_ERROR` 记号 —— `test_diode.py` 断言它是 `None`。

`add_component` 的 schema 文案现在从 `PART_META` 生成，所以 Agent 看到的
`tools/list` 里直接就有：

```
  family=DIODE, part=1N4007G（引脚 A/K，**不接受 value**；
    SPICE 模板 `d%p %tA %tK %m`；donor Fuente capacitiva final.ms14[D2]）
    ⚠️ 只支持一种拓扑：V1 -> D1 -> R1 -> GND 的半波整流……
```

**文案和实现同源**，不会出现"文档写了但代码没实现"。

### 2.3 layout：一个模板 + 一道闸门

既有 6 类拓扑（`shunt_load` / `series_chain` / `divider` / `bypass` / `tee` / `ladder`）
的 `plan()` 代码**一个字节没动**，因为它们的坐标被 3 次真机验收固定住了。新拓扑走新表：

```python
KIND_TEMPLATES = {
    "halfwave_rectifier": {"series_offset": (0.5, 0.0), "shunt_offset": (0.0, 0.0), ...},
}
```

`_classify()` 里必须把 `halfwave_rectifier` **排在 `divider` 之前**判 ——
否则"二极管 + 电阻到地"会被当成"电阻分压"（因为到地的那个是电阻），
名字错了后面全跟着错。

真正的硬活在准入闸门 `_check_diode_topology()`。二极管在 donor 里是**竖直符号**
（A 在下、K 在上），和已经验过的电阻/电容朝向不同；而且"整流"没法用正弦拟合验证。
所以这一版只放开一种接法，其余全部明确拒绝：

| 拒绝原因（`context.reason`） | 触发条件 | 提示 |
|---|---|---|
| `diode_multiple` | 电路里 >1 个二极管 | 全波 / 桥式没验过 |
| `diode_with_capacitor` | 出现电容 | 电容滤波 / 峰值检波没验过 |
| `diode_template_unverified` | 判定出来的不是半波整流 | 只放开 V1→D1→R1→GND |
| `diode_not_first_series` | 二极管不在源之后第一个串联位 | 把 D1.A 直接接源正极 |
| `diode_load_not_resistor` | 到地的不是单个电阻 | 只验过电阻负载 |

**这是刻意的"不通用"。** 先让一种拓扑电气可验证，再谈扩展。

## 3. 闭环证据

### 3.1 Agent 视角的调用序列（14 次，0 失败）

`run_diode.py` 每次调用起一个独立进程（v0.8 的设计），Agent 拿不到进程内状态，
也不可能 import 项目模块。

```
tools/list            -> 8 个工具，schema 里有 DIODE/1N4007G
create_circuit        -> c-1746e09c52
add_component ×4      -> V1(5V/50Hz) D1(DIODE/1N4007G) R1(1k) GND1
connect ×3            -> in=[V1.+,D1.A]  out=[D1.K,R1.1]  0=[V1.-,R1.2,GND1.1]
add_probe ×2          -> P_in, P_out
simulate              -> 19.4 s（compile 15.3 s / run 4.1 s），n=10000
measure               -> mode="rectifier"
get_waveform          -> artifact=halfwave_1n4007g.csv
get_circuit           -> 4 元件 / 3 网络 / 2 探针
```

### 3.2 真机数据 vs 独立复算

`run_diode.py` 的复算部分**只读 CSV**，不 import 任何项目模块：

| 量 | 实测 | 独立复算 | 判定 |
|---|---|---|---|
| 输出峰值 | 4.3696 V | 4.3696 V | 一致（差 0） |
| 输出最小值 | −0.00010 V | −0.00010 V | 反偏确实截止 |
| 直流分量 | 1.3051 V | 1.3051 V | 一致（差 0） |
| 深导通压降（v_in ≥ 0.8Vm） | — | **0.6200 ± 0.0036 V**（n=2042） | 落在 1N4007 合理区间 |
| 反偏区最大 \|v_out\| | — | **1.11 mV** | < 5 mV |
| 导通占比 | 0.4861 | 区间 (0.4573, 0.5) | 区间内，pos=0.674 |

`measure` 自己算的和独立复算**逐位相同**（差 0.00e+00）—— 因为它俩读的是同一个 CSV，
算法也都在文档里写着。这不算"独立验证"，但至少排除了"两套代码算出两个数"。

真正有信息量的是**物理校验**：

- 深导通区压降 `0.6200 ± 0.0036 V`（标准差 3.6 mV）—— 说明 donor 里的 1N4007G
  模型是真的二极管模型，不是一个恒定压降的理想开关。
- 反偏漏电 1.11 mV —— 反向截止成立。
- 直流分量落在 `(Vm/π − Vf/2, Vm/π) = (1.2775, 1.5895)` 之间，`pos=0.089`
  （贴近下界）—— 因为大部分导通时间里压降确实接近 0.62 V。

### 3.3 两个"差点做错"的地方

**这两个都是上一轮报告里被掩盖的问题，值得单独写下来。**

#### (a) 上一轮"二极管通过"其实只注册了一个探针

上一轮 `_probe_diode.py` 的输出是 `outputs=['V(探针2)']` —— **只有一个通道**。
当时我只看输出波形对上了（`max=4.3751`），就标了"通过"。这次换成走 MCP 才发现：
两个探针里少了一个。

根因：`ir_compile` 把探针放在网络导线顶点的 `vs[1]`（拐点）。二极管的几何让那个拐点
**正好落在二极管阴极上**，而阴极属于**另一条网络** —— 探针于是挂到了错误的位置。

修法（`ir_compile._pick_probe_xy`）：**默认取法不变**（已验收的电路全靠它），
只有当那个顶点"正好是别的元件的引脚"时才换一个本网络自己的顶点。
老电路上这个条件永远不成立，所以 5 种元件的行为一个字节都没变。

修完 `outputs=['V(探针1)','V(探针2)']`，两个都在。

> 教训：**"能跑出正确波形"不等于"闭环通了"。** 少一个探针时波形依然对，
> 只是你少看了一个量。上一轮那个"通过"标早了。

#### (b) 恒定压降模型只在深导通区成立

第一版 `measure` 写的是 `Vdc = Vm/π − Vf/2`，拿实测去卡，结果：

- 直流分量差 **2.0%**（卡在阈值上）
- 导通占比差 **2.9 个百分点**（直接 FAIL）

查波形才明白：`Vf = 0.62 V` 只在深导通区成立。实测逐点压降：

| 区间 | Vf 均值 | 说明 |
|---|---|---|
| `v_in > 0.8Vm` | 0.6200 ± 0.0036 V | 确实是常数 |
| `0.3Vm ~ 0.8Vm` | 0.5894 V（0.547~0.612） | 指数段，开始下滑 |
| 刚开启 | 0.4476 V（低到 0.128 V） | 开启点远低于饱和压降 |

所以导通比恒定压降模型预测的**更早开始**，直流分量也就比它算的**高一点**。
这不是电路错了，是**模型太粗**。

改法：理论值给**区间**而不是点值。

```
Vdc      ∈ (Vm/π − Vf/2, Vm/π)      恒定压降是下界，理想二极管是上界
导通占比 ∈ (恒定压降模型, 0.5)       同理
```

实测必须落在区间内，`bracket.pos` 告诉你偏向哪一端（0 = 恒定压降端，1 = 理想端）。
实测 `pos` 分别是 0.089 和 0.674 —— 前者贴近下界（导通时压降确实约 0.62 V），
后者贴近上界（开启点很低）。**两个方向都符合物理**，这才是有信息的校验。

> 把实测硬塞进一个粗糙模型的点值上，只会得出"模型不准"这个结论，
> 而真正该记下来的是"模型在哪个区间成立"。

## 5. 这套机制适不适合扩 BJT_NPN？

分开评，因为两层的结论**相反**。

### 5.1 ComponentSpec 层：✅ 可以直接复用，成本≈0

加一种元件要动的只有两处：

1. `registry/components.json` 的 `enabled` 加一行 —— 引脚、几何、SPICE 模板、donor
   全部现成（`BJT_NPN/2N2222A` 已经在目录里：引脚 `B/C/E`，模板
   `q%p %tC %tB %tE %m`，donor 在官方样例里）。
2. `PART_META` 里补一段**语义声明**：`value` / `extra` / `analyses`。
   NPN 的 `n_params = 0`，所以 `value=None` 可以直接推出来，**不用手写**。

也就是说：**"让 MCP 接受 BJT_NPN/2N2222A"这件事，现在只是改一行 JSON 的事。**

但接受了没用 —— 会卡在下一层。

### 5.2 layout 层：❌ 不能复用，这是真正的工作量

`analyze()` 的整个图模型建立在**两端元件**上：

```python
def _two_pin_other(comp, pin):     # layout.py
    others = [p for p in pins if p != real]
    return others[0] if len(others) == 1 else None   # ← 三端直接返回 None
```

三端器件走到这里就报 `non_two_pin`。而且这不是"加个模板"能解决的：

- `analyze()` 的主干遍历假设"一个节点 → 一条向下的主干"。三端器件有**第三个引脚
  要去别处**（基极接偏置、发射极接地、集电极接负载），这打破了单主干假设。
- 即使是最简单的"二极管接法"（B/C 短接、E 接地），`Q1.B` 和 `Q1.C` 会同时出现在
  一条网络上 —— 仍要走三端路径，不能当两端处理。

所以 NPN 至少需要：

| 改动 | 位置 | 量级 |
|---|---|---|
| `analyze()` 支持"三端元件 + 引脚到网络的映射" | `layout.py` | **大**（图遍历要重写一层） |
| 1~2 个拓扑模板（共射 / 射极跟随器） | `KIND_TEMPLATES` | 中 |
| 准入闸门（像 `_check_diode_topology` 那样逐条拒） | `layout.py` | 小 |
| `measure` 加直流工作点分支（V_BE / V_CE / I_C） | `circuit_session.py` | 中 |
| 探针落点规则重验（引脚更多，撞引脚的概率更大） | `ir_compile.py` | 小 |
| 测试 + 真机验收 | `test_bjt.py` / `run_bjt.py` | 中 |

**结论：BJT 的工作量比二极管大一个量级，主要压在 `layout.py` 的图模型上，
不在 registry 上。**

### 5.3 建议的下一步

如果要做 NPN，建议按这个顺序，每步都能独立验收：

1. **先只做"共射 + 分压偏置"一种拓扑**，和二极管一样严格准入、其余全拒。
   不要一上来做"通用三端"。
2. **`analyze()` 的新分支单独写**（`_analyze_three_terminal()`），不要改现有主干遍历 ——
   否则 6 类已验证拓扑会跟着动。
3. **先验静态工作点（dc 分析），再验放大（transient）**。dc 分支已经有现成的
   `simulate_dc` 和 `theory_dc`，改造成本比瞬态低。
4. `PART_META` 里 NPN 的 `analyses` 要显式声明 —— 它不是电源，但需要 dc + transient
   两种分析，别让它落进"无源元件"那条默认路径。

## 6. 边界（这一版**没有**做的事）

- **没有**放开第二种二极管型号。`DIODE/1N4001`、`1N914` 在目录里但不在 `enabled`。
  （`1N914` 的 donor 是**水平**符号，几何和 1N4007G 不同，得单独验。）
- **没有**支持电容滤波 / 峰值检波。二极管 + 电容会被明确拒绝。
- **没有**支持全波 / 桥式整流。
- **没有**做 GUI 自动化，也**没有**再碰 COM 元件库接口（上一轮已排除）。
- **没有**把 192 种元件批量放开。`enabled` 只有 1 项，这是刻意的。
- **没有**改 `measure` 的正弦拟合路径（RC / 分压等仍走原逻辑）。

## 7. 怎么复现

```bat
:: 0) 重建 registry（可选，仓库里已经有一份）
runtime\py32\python.exe tools\build_registry.py

:: 1) 纯逻辑测试，不需要 Multisim（62 项）
runtime\py32\python.exe tools\test_diode.py

:: 2) 端到端验收，会开 Multisim（约 26 s）
taskkill /F /IM multisim.exe
runtime\py32\python.exe tools\agent_acceptance\run_diode.py

:: 3) 回归：一阶 RC 还对不对
set RC_WD=out/agent_v09/rc_regression
runtime\py32\python.exe tools\_rerun_rc.py
```

产物：

```

out/agent_v09/diode/halfwave_1n4007g.csv     10,000 点  两路波形
out/agent_v09/diode/trace.jsonl              14 条      完整 tool call / result
out/agent_v09/diode/acceptance.json          断言明细 + 复算结果
out/agent_v09/rc_regression/trace.jsonl      回归证据
registry/components.json                     192 种元件的 ComponentSpec
```

看输出是不是"正半周通过、负半周被削平"。
