# 分支感知布局（P2 / v0.7.0）

> 一句话：**让已经成立的 MCP 电路语义，第一次跨过多分支拓扑这道执行层门槛。**
>
> 代码：`tools/layout.py`（拓扑分析 + 坐标）
> 测试：`tools/test_layout.py`（51 项，纯逻辑，不需要 Multisim）
> 验收：`out/agent_test2/run_task2.py`（**一行没改**，从被拒变成跑出数）

---

## 1. 为什么需要这一版

第二次 Agent 验收（v0.6.1）证明了一件很干净的事：外部 Agent 只读
MCP `tools/list`，就能把二阶 RC 低通**正确表达**出来 —— 16 次调用零错误，
建出教科书式的梯形网络：

```
in  [V1.1, R1.1]
n1  [R1.2, C1.1, R2.1]      ← 三引脚节点
n2  [R2.2, C2.1]
0   [C1.2, C2.2, V1.2, GND1.1]
```

然后第 17 步 `simulate` 被拒：

```json
{"code": "LAYOUT_UNSUPPORTED",
 "message": "网络 'n1' 有 2 个分支（C1.1, R2.1）",
 "hint": "第一版只支持串联链；并联 / 多支路的布局还没验证过。",
 "context": {"net": "n1", "branches": ["C1.1", "R2.1"]}}
```

于是问题被分成了两半：

| 层 | 结论 |
| --- | --- |
| MCP 语义层 | ✅ 够用 —— 多节点电路能准确表达，一次就对 |
| 后端布局层 | ❌ 挡住 —— `plan_layout()` 只认单链、`MAX_PASSIVES = 2` |

P2 要解决的是**下面那一半**。它不改任何电路语义、不改 API、不改仿真核心，
只把"布局"从"走一条链"升级成"先判断拓扑、再生成坐标"。

## 2. 一条必须说清楚的事实：坐标不影响连通性

这是这一版最重要、也最容易被误解的一点。实测依据：

```python
# tools/ir_compile.py
node_id = a.connect(members, name=net.name)     # members 来自 net.pins 显式列表
```

```python
# tools/msbuild.py :: connect()
for i in range(len(resolved) - 1):
    self.wire(node_id, resolved[i], resolved[i + 1])   # 导线只是画出来
```

网表由 **IR 里 `nets` 的显式引脚列表**决定，坐标只决定两件事：

1. 符号画在哪；
2. `connect()` 按引脚顺序连出来的折线长什么样。

所以布局器**不负责**"把电路连对"。它的职责只有两条：

- **准入门槛**：这个拓扑我们验过吗？没验过就明确拒绝，不硬排；
- **可读坐标**：给一套不重叠、能看出层级的坐标。

这条事实把 P2 的风险从"电气正确性"降到了"准入判断准不准"。
也正因为如此，P2 才有底气在**完全不碰** `ir_sim` / `ir_compile` /
`msbuild` / `mssafe` 的前提下做完。

> **但"坐标不影响连通性"不等于"坐标可以乱给"。** 第 6 节有一个反例：
> 导线横穿别的元件符号时，Multisim 会少认一个探针通道。
> 所以坐标仍然要遵守一条几何约束：**导线不能穿过别的符号框**。

## 3. 结构：拓扑判断先于坐标布局

这是用户定的原则，也是这一版唯一的结构性改动。

```
Circuit IR
  → layout.analyze()     纯图论：这是什么拓扑？支路在哪？属于哪个模板？
  → layout.Topology      结构化描述（stages / shunt / out_net），不含坐标
  → layout.plan()        按拓扑生成坐标
  → {refdes: [x, y]}
  → ir_compile           → .ms14
```

反过来的写法（先试着摆坐标、摆不下再报错）会有一个长期后果：
以后每加一种电路，都要去改坐标代码，而且错误总是出在坐标层，
而真正的原因是"拓扑没被表达"。分开之后：

- `analyze()` **不认识坐标**；
- `plan()` **不认识电路语义**；
- 两者都能单独测（`test_layout.py` 全程不需要 Multisim）。

`circuit_session.plan_layout()` 现在只做一件事：把 `LayoutError`
转成对外的 `SessionError`。会话层不再有拓扑逻辑。

## 4. 支持的拓扑类：单主干 + 到地并联支路（ladder）

一条从电源正极出发、逐级向下的主干；每级最多一个到地的并联元件；
电源负极接地。

```
V1(+) ──[R1]──●──[R2]──●── ...
              │        │
             [C1]     [C2]
              │        │
              └────────┴── GND
```

`analyze()` 从 `in` 网开始，每走一级就判断：

- 相邻元件的另一端在 **地网** 上 → 这是**到地并联**（shunt）；
- 否则 → 这是**下一级串联**（series）；
- 两者都记进 `Stage(index, net, series, shunt)`。

最后按"串联数 / 到地数 / 元件类型"给出模板名：

| kind | 结构 | 例子 | 备注 |
| --- | --- | --- | --- |
| `shunt_load` | 0 串联 + 1 到地 | 直流 5V + 1kΩ | v0.5.0 的验收电路 |
| `series_chain` | N 串联 + 0 到地 | 空载串联 | 输出开路，`validate()` 会另拦 |
| `divider` | 1 串联 + 1 到地（电阻） | 电阻分压 | |
| `bypass` | 1 串联 + 1 到地（电容） | 一阶 RC 低通 | v0.6.0 的验收电路 |
| `tee` | 2 串联 + 1 到地（电阻，中间级） | T 型网络 | |
| `ladder` | 其它（≥2 串联，≥1 到地） | **二阶 RC 梯形** | P2 的验收目标 |
| `parallel_shunt` | 某节点挂 2 个到地元件 | 分压 + 旁路电容；RC 并联负载 | v0.10.0 新增，见第 13 节 |

**关于"只做 3 个模板"这条边界**：`divider` / `bypass` / `tee` 是点名要的
三个具名模板，全部实现并测试。但**验收题本身是二阶 RC**（2 串联 + 2 到地），
它不属于这三个中的任何一个 —— 所以 `ladder` 不是"偷偷扩功能"，而是这一版
绕不过去的必需项。实现上它和三个模板共用同一套 stages 模型，
没有引入第二套机制。

`shunt_load` / `series_chain` 是退化情形，v0.5.0/v0.6.0 已经在跑，
必须继续支持。

## 5. 明确拒绝的拓扑

拒绝不是"排不出来"，是"这类还没验过"。两者的错误信息必须不同，
所以每条都带 `context.reason`：

| reason | 含义 | 例子 |
| --- | --- | --- |
| `fork` | 一个节点有 2 条向下的主干 | ~~两组 RC 并排~~ **v0.11.0 已放开**，见第 14 节；跨级连接（反馈 / 桥接）仍会先在这里被拦下 |
| `parallel_shunt` | 一个节点有 **3 个及以上**到地元件 | 2 个已在 v0.10.0 放开；3 个没验过 |
| `island` | 元件和电源不连通 | 悬空元件、独立子电路 |
| `open_pin` | 元件的另一端没接线 | 连了一半 |
| `cycle` | 拓扑回到走过的节点 | 环路 / 反馈（防御性检查） |
| `too_many_stages` | 主干级数 > 4 | 不是做不到，是超过 4 级时符号排布没实测过 |

另外三个独立错误码（不是 `LAYOUT_UNSUPPORTED`，因为它们是电路前提问题）：

| code | 含义 |
| --- | --- |
| `MULTIPLE_SOURCES` | 多电源（含运放双电源供电）还没验证 |
| `NO_GROUND` / `MULTIPLE_GROUND` | 地缺失 / 多于一个 |
| `SOURCE_NOT_GROUNDED` | 电源负极没和 GROUND 同网络 —— P2 的单电源前提不成立 |

实测报错样例（并联到地）：

```json
{"code": "LAYOUT_UNSUPPORTED",
 "message": "网络 'in' 有 2 个到地元件（R1, R2），是并联到地",
 "hint": "P2 每一级最多一个到地元件。两个元件并联到地（比如电阻和电容并联）还没验证过；拆成一个元件，或先用两个电路分别验。",
 "context": {"reason": "parallel_shunt", "net": "in", "shunts": ["R1", "R2"]}}
```

## 6. 一次真跑出来的几何 bug（这条比坐标规则本身更重要）

第一版网格是"每一级就在自己的 x 上，并联元件挂在下面"，于是
**第 0 级和电源挤在同一列**：

```
V1  (300,300)
R1  (300,460)   ← 第 0 级的到地元件，正好在电源正下方
GND (300,620)
```

跑直流验收（5 V + 1 kΩ 到地）时，`simulate` 只返回了**一个**通道：

```json
"outputs": ["V(探针1)"],
"summary": {"P1": {"n": 1, "mean": 5.0}},
"probes": [{"probe_id": "P1", "output": "V(探针1)", "net": "in"},
           {"probe_id": "P2", "output": null,        "net": "0"}]
```

`P2` 落在 `0` 网上，但 Multisim 没给它任何输出。原因不是探针逻辑、
不是 `EnumOutputs` 缓存、也不是直流分析本身 —— 是几何：

```
0 网导线链：[R1.2, V1.2, GND1.1]
  R1.2 (300,478) → V1.2 (300,318)      ← 这条竖直导线穿过 R1 自己的符号框
  V1.2 (300,318) → GND1.1 (300,602)
```

一条从 R1 下引脚竖直向上走回电源负极的导线，**横穿了 R1 的符号框**。
Multisim 只认出了一个探针通道。

修法：**电源独占最左一列，各级从 `X0 + DX` 开始**。

```
V1  (300,300)
R1  (540,460)   ← 右移一格，导线不再穿任何符号
GND (300,620)
```

改完立刻恢复：`P1` 5.000000 V、`P2` 0.000000 V、`R=1000 Ω`、`I=0.005000 A`。

这条 bug 的教训值得单独记下来：

> **"坐标不影响连通性"是对的，但"坐标随便给都行"是错的。**
> 网表确实由 `nets` 决定，可是 Multisim 在读文件时会把
> "导线穿过符号"当成异常几何，直接少给一个探针通道 —— 表现为
> "仿真成功但没有数据"，很容易被误判成 COM 问题。

对应的保护写进了 `layout.py` 的 `_col_x()` 注释里，免得以后有人
"优化"成从 `X0` 开始又踩一遍。

## 7. 一处配套改动：`validate()` 提到拓扑判断之前

`simulate()` 原来的顺序是：

```
布局 → 算仿真参数 → validate()
```

改成了：

```
算仿真参数 → validate() → 拓扑 + 布局
```

原因：一个"元件没接线"的电路，从拓扑层看是 `island`（"这些元件和电源不连通"），
但 Agent 真正需要的是 `validate()` 给出的具体信息（"R2 的引脚 2 没接"）。
校验先跑，错误更准。

> 踩过的坑：第一次改成"`validate()` 最前面"，`simulate` 直接报
> `simulation.stop 必须大于 0（0）` —— 因为 `stop` 是按源频率在后面推出来的。
> 顺序必须是 **参数 → 校验 → 拓扑**，不能再往前挪。
> 这个失败是原样跑 `run_task2.py` 撞出来的，不是我推断的。

## 8. 坐标规则

```
X0 = 300      DX = 240
Y_MAIN = 300  Y_SHUNT = 460  Y_GND = 620

第 i 级的列：      x_i = X0 + DX*(i+1)        → 540, 780, 1020
第 i 级串联元件：  (x_i + DX/2, Y_MAIN)       → 660, 900
第 i 级到地元件：  (x_i, Y_SHUNT)             → (540|780|1020, 460)
电源：            (X0, Y_MAIN)                → (300, 300)

```

二阶 RC 的实际坐标：

| 元件 | 坐标 | 含义 |
| --- | --- | --- |
| V1 | (300, 300) | 源（独占最左列） |
| R1 | (660, 300) | 第 0 级串联（in → n1） |
| C1 | (780, 460) | 第 1 级到地（n1） |
| R2 | (900, 300) | 第 1 级串联（n1 → n2） |
| C2 | (1020, 460) | 第 2 级到地（n2） |
| GND1 | (300, 620) | 地 |

> `源(300,300) / 无源(500,300),(700,400) / 地(300,420)`，只能摆 2 个无源元件。

## 13. v0.10.0：同一节点 2 个到地元件（`parallel_shunt`）

第 5 节里 `parallel_shunt` 是"明确拒绝"，理由是"两个元件并联到地还没验过"。
v0.10.0 把它放开了 —— 只放到 2 个，3 个仍然拒绝。

### 13.1 为什么先挑这一类

它不是"又一种拓扑"，而是教学电路里出现频率最高的一张图：

| 电路 | 形状 | 用途 |
| --- | --- | --- |
| 分压 + 旁路电容 | 1 串联 + (R ∥ C) 到地 | 静态工作点 + 交流旁路 |
| RC 并联负载 | 1 串联 + (R ∥ C) 到地 | 带宽受限的衰减器 |
| 电阻并联 | 0 串联 + 2 个 R 到地 | 等效电阻 |

`fork`（一个节点分出两棵子树）当时仍然拒绝 —— 它是**递归布局**问题，
不是加一个偏移量能解决的。**v0.11.0 已单独用 `tools/layout_tree.py` 解决，见第 14 节。**

### 13.2 数据结构：`shunt` → `shunts`

```python
class Stage:
    shunts = ["C1", "R2"]     # 真实存储，0/1/2 个
    @property
    def shunt(self):
        return self.shunts[0] if self.shunts else None    # 老代码的只读别名
```

保留 `shunt` 别名是刻意的：v0.1~v0.9 的代码、测试、文档都只认"一级一个到地
元件"，有别名就不用改它们，也就不会把已验收的行为改坏。代价是**新代码不能
再用 `shunt`** —— 它会悄悄忽略第 2 个元件。`to_dict()` 两个字段都给，Agent
两边都能读。

`n_shunt` 的口径也跟着改了：现在是**数元件**，不是数"有到地的级数"。
一个节点挂 2 个，`n_shunt = 2`。

### 13.3 几何：只加一个偏移量

```
              ● n1 ────[R2]───┐        ← 第 2 个到地元件往右挪半格
              │                │
   [R1]───────┤                │
              │                │
             [C1]              │
              └────────────────┴── 0
```

```python
SHUNT_DX = DX / 2.0          # 120

def _shunt_offset(j, k):     # 第 j 个（共 k 个）
    if k <= 1:
        return 0.0           # ← 单个到地元件的坐标一个字节都没变
    return (j - (k - 1) / 2.0) * SHUNT_DX      # k=2 → −60 / +60
```

`k == 1` 时返回 0 是关键：v0.1~v0.9 的所有电路坐标保持逐位不变，
有回归测试守着（`test_layout.py` 的"回归：单并联元件仍在本级列正中"）。

为什么不改 Y？两个元件摆在同一行、以本级列为对称轴，"并联"这件事在图上
是一眼可见的；错开 Y 反而会让人以为是两级串联。

### 13.4 理论值：`acmodel.py`

以前 `theory()` 只认 1R+1C，二阶以上的电路拿不到理论值，验收脚本只能手算。
v0.10.0 抽出一个纯数学模块 `tools/acmodel.py`，用**复数阻抗 + 从末级往回算
输入阻抗**的递推：

```
Z[i] = 并联( 本级的到地元件 , 串联元件 + Z[i+1] )
H_i  = Z[i+1] / ( 串联元件 + Z[i+1] )
H    = Π H_i
```

好处是"同一节点两个到地元件"自动就是 R∥C，不需要为每种组合单写公式。
只认 R / C；出现二极管、电感返回 `None` —— 宁可没有理论值，也不给一个
"能算但错"的数。

抽成独立文件的原因很实际：`ir_sim` 一 import 就拉 COM，没有 Multisim 的机器
连理论值都算不了。理论值是"独立复算"的基础，必须能在任何机器上跑。

## 14. v0.11.0：分叉树（`fork`）

第 5 节里 `fork` 是"明确拒绝"，第 12 / 13 节两次把它列为"递归布局问题，不是加偏移量能解决的"。
v0.11.0 解决了它 —— 但不是把它塞进老的 `analyze()` 循环。

### 14.1 为什么单独一个模块

`layout.py` 的 `analyze()` 走的是**单主干**模型：从电源正极出发一路向下到地，
每个节点只能有一条往下的主干。这个模型被 v0.1~v0.10 的 6 次真机验收固定住了，
**坐标一个字节都不能动**。

分叉是另一个模型。塞进老循环只有两条路：改动老路径的坐标，或者让老代码长出一堆
`if fork` 分支 —— 两者都是拿已经验证过的东西冒险。所以独立成 `tools/layout_tree.py`：

```python
# layout.py analyze()
if _has_fork(ir, src.refdes, gnd.refdes, gnd_net, in_net):
    import layout_tree
    return layout_tree.analyze_tree(ir, src, gnd, in_net, gnd_net)
# 以下单主干循环一行都不执行
```

`plan()` 同理，用 `getattr(topology, "root", None) is not None` 区分树形拓扑，
而不是 `isinstance` —— 这样 `layout_tree` 不需要反向 import `layout`。

### 14.2 怎么判定"分叉"

判据不能只数"这个网络上挂了几个非地元件" —— 单主干的**中间节点本来就有 2 个**
（一个从上游进来、一个往下去）。所以按入度分：

| 节点类型 | 入 | 出 ≥ 2 的条件 | 非地元件数阈值 |
| --- | --- | --- | --- |
| 普通节点 | 1 | 非地元件数 ≥ 3 | `n > 2` |
| 根节点 | 0 | 非地元件数 ≥ 2 | `n > 1` |

只看两端元件（`_two_pin_other` 对多引脚返回 `None`，直接跳过）——
运放 / 555 不该把电路误判成树形，它们走的是另一条布局路径。

这个扫描刻意做在 `analyze()` 主循环**之前**：一旦判定是分叉，整棵树交给
`layout_tree`，单主干那条路径一行都不执行。

### 14.3 几何：向下 = 深度，向右 = 支路

```
        V1 ──┬──────────┬
             R1         R2
             │          │
             C1         C2
             │          │
             └────┬─────┘
                 GND
```

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `COL` | 240.0 | 支路列距（元件符号宽约 40，留出能看清的空白） |
| `STEP` | 110.0 | 一个元件占的垂直高度（引脚 ±22.5，剩 65 空隙） |
| `Y_TOP` | 200.0 | 第一层节点的 y |
| `GND_DY` | 130.0 | 地符号相对最深层的距离 |

* 节点（网络）本身没有符号，是一条水平接线
* 源放在根的**左边同一行**，一眼看出"从这里分出去"
* 地放在最下方、和根**同一列**，所有到地支路沿竖线下来再横向汇合
* 同层支路按子树宽度分列：`node.x = x_left + (cols − 1)·COL/2`，保证子树居中

### 14.4 走线为什么必须由布局器指定

两个引脚之间的 L 形折线（`wire` 的 `"hv"` / `"vh"`）在这里不够用：

* 源要同时连到左右两条支路，而**源符号自己挡在中间**，任何 L 形都会穿过它；
* 分叉节点的几条支路要汇到同一条水平线上，L 形会把竖线压在兄弟支路的引脚上。

所以给每条网络算出**折点**（`wiring_hints`），由 `wire_via` 画。
折点的首尾不用管：`wire_via` 用实际引脚坐标，布局器只给中间几个拐点。
对应 IR 新增三个纯几何字段（`route` / `star` / `routes` / `tap`，见 `circuit_ir.Net`）。

还有一个坑：两点直线（比如"串联元件下引脚 → 到地元件上引脚"，同一条竖线）
**没有中间顶点**，而探针只能落在顶点上 —— 探针被迫落在引脚上，真机实测会**丢通道**。
`wiring_hints` 给这类网络打 `tap=True`，编译时在正中插一个共线折点：
看起来还是直线，但探针有地方放了。

### 14.5 第一版为什么失败：水平泳道

第一版把支路画成**水平泳道**，真机直接失败。原因很实在：Multisim 的电阻/电容 donor
是**竖直符号**（引脚在上下，中心 ±22.5），不是水平的。水平泳道会让"两个元件之间的
导线"变成一条水平直线、没有拐点，探针只能落在引脚上 —— 3 个探针只注册上 2 个。

这就是 14.4 那个 `tap` 的由来，也是"顺着符号本身的朝向摆"这个决定的由来。

| Case | 电路 | 实测 | 理论 | 验的是 |
| --- | --- | --- | --- | --- |
| A | `V1(1V/1kHz) - in ─┬─ R1(1k) - n1 - C1(159.155n) - GND`<br>`└─ R2(2k) - n2 - C2(159.155n) - GND` | 支路1 `0.70587∠−45.10°`<br>支路2 `0.44596∠−63.51°` | `0.70711∠−45.00°`<br>`0.44721∠−63.43°` | **电气**：两条支路各算各的 |
| B | `V1(5V DC) - R1(1k) - n1 ─┬─ R2(1k) - n2 - R4(1k) - GND`<br>`└─ R3(1k) - n3 - R5(1k) - GND` | n1 = **2.500000 V**<br>n2 = n3 = **1.250000 V** | 2.5 / 1.25 | **几何**：DC 对"导线穿符号"最敏感 |
