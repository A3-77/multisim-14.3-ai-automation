## 1. 电路设计：拓扑与"二阶"的保证

### 1.1 可用元件决定的约束

执行器只接受 5 种元件：`AC_VOLTAGE`、`DC_POWER`、`RESISTOR`、`CAPACITOR`、`GROUND`。没有运放，也没有电感。
这直接排除了两条常规的二阶低通路线：

- **Sallen-Key / MFB（有源二阶）**：需要运放，不可用；
- **RLC 二阶**：需要电感，不可用。

只剩一种可能：**用两个独立储能元件（两只电容）构成两节 RC 的级联**。二阶性不来自"两个一阶级联"这个说法本身，
而来自网络里存在 **2 个独立状态变量**，因而传输函数分母是 s 的二次式。

### 1.2 选定拓扑：无源 RC 梯形网络（ladder）

```
        R1=1k          R2=10k
 in o──/\/\/\──┬──/\/\/\──┬──o out
               │           │
             C1=47n      C2=4.7n
               │           │
 0 o───────────┴───────────┴──── (GND1)
```

节点：`in`（源正极）、`mid`（R1/R2/C1 交点）、`out`（R2/C2 交点）、`0`（地）。

### 1.3 怎么保证它真的是二阶（而不是"两个一阶相乘"的错觉）

两点，都做了数值核对：

1. **拓扑上**：两只电容不共节点（C1 在 `mid`，C2 在 `out`），所以是两个独立状态变量，分母必然是二次式。
   若把两只电容并在同一节点上，那只是一阶（C1+C2 并联），这一点我在布线时刻意避免了。
2. **解析上**：对上述网络做复数节点分析，分母确实是

   ```
   D(s) = 1 + s·(R1C1 + R2C2 + R1C2) + s²·(R1C1·R2C2)
        = 1 + s·9.87e-5 + s²·2.209e-9
   ```

   二次项系数 2.209e-9 s² 非零 ⇒ 二阶。两个极点（实极点，因 Q<0.5）：

   - p1 = −15528 rad/s → **2471 Hz**
   - p2 = −29152 rad/s → **4640 Hz**
   - 乘积 = 1/(R1C1R2C2) = 4.527e8 ✓

   高频段 |H| ∝ 1/ω²，即 −40 dB/dec，这是二阶的标志性斜率（一阶只有 −20 dB/dec）。

### 1.4 为什么是"无源级联"而不是"两节独立 RC 直接相乘"

这是本设计里唯一需要解释的取舍。无源级联时，第二节对第一节有**加载效应**，因此

```
H(s) ≠ H1(s)·H2(s)
```

真实分母里多出一项 `R1C2`（即上式的 a1 = τ1+τ2+R1C2，而不是 τ1+τ2）。我按**含加载的完整二阶式**算理论值，
没有用"两个一阶相乘"的近似——后者会算出 0.9198（偏高 1.50%）、相位 −32.90°（比真值 −34.19° 少了 1.3°），
是个典型的错误来源：忽略加载会同时高估增益、低估相移。

加载效应同时限制了品质因数。对无源两级 RC：

```
Q = √(τ1τ2) / (τ1 + τ2 + R1C2) ≤ 0.5
```

上限 0.5（在 τ1=τ2 且 R1C2→0 时取到）。也就是说**无源两级 RC 永远做不出 Butterworth 的 Q=0.707**，
通带一定有一点下垂、−3dB 点一定低于自然频率 f0。这一点在报告第 3 节里用"fc 的定义"如实交代，
而不是把 f0 冒充成 fc。

## 2. R / C 参数

| 元件 | 数值 | 是否标准值 | 说明 |
|---|---|---|---|
| R1 | 1 kΩ | 是（E6/E12） | 取较低阻值，减小第二节对第一节的加载 |
| R2 | 10 kΩ | 是（E6/E12） | R2/R1 = 10，使 R1C2 项（4.7 µs）远小于 τ1+τ2（94 µs） |
| C1 | 47 nF | 是（E6/E12） | |
| C2 | 4.7 nF | 是（E6/E12） | 与 C1 保持 10:1，配合 R 的 1:10，令 τ1 = τ2 |

设计意图：

- **τ1 = R1C1 = 47 µs，τ2 = R2C2 = 47 µs**，两者相等 → Q 取到该结构的接近上限（实测 Q = 0.4762，理论上限 0.5）；
- **R1C2 = 4.7 µs**，只占 a1（98.7 µs）的 4.8%，加载效应被压到很小，通带平坦度好；
- 阻抗水平取 1 kΩ 量级：对源不至于重载，电容落在 4.7 nF ~ 47 nF 这种容易买到的档位；
- 全部是 E6/E12 标准值，没有为了凑 fc 去用 47.9 nF 这种非标值。

> 代价：因为用了标准值（47 nF 而非 47.9 nF，−1.88%），fc 从 2000 Hz 偏到 2034 Hz（+1.71%）。
> 这是**设计偏差**，我如实保留，没有回头改参数去"美化"结果。

Multisim 回读的元件值（`simulate` 返回的 `rlc_reported_by_multisim`）：
`R1=1000.0, R2=10000.0, C1=4.7e-08, C2=4.7e-09` —— 与我设定的一致，说明参数确实写进了网表，不是"我以为是"。

## 3. 实际截止频率，以及二阶滤波器 fc 的定义

### 3.1 我的 fc 定义

**fc ≡ |H(jω)| 下降到通带（直流增益 = 1）的 1/√2，即 −3.01 dB 的频率。**

这是工程上通用的 −3dB 定义，也是"截止频率"唯一有物理意义的口径。我**没有**用 f0 = 1/(2π√(R1C1R2C2)) 当 fc——
在 Q≠0.707 的网络里，f0 只是分母的几何中心，不是 −3dB 点。二者在本设计里差得很远：

- f0（自然频率）= 3386.3 Hz
- **fc（−3dB）= 2034.3 Hz = 0.601·f0**

比值 0.601 是 Q=0.4762 时的必然结果，可由 (1−u²)² + (u/Q)² = 2 解出 u = 0.601，与数值二分结果一致。

### 3.2 结果

| 量 | 值 | 来源 |
|---|---|---|
| fc（−3dB，解析+数值二分） | **2034.3 Hz** | 我的脚本 |
| 目标 | 2000 Hz | 题目 |
| 偏差 | +34.3 Hz / **+1.71%** | 设计偏差（标准值量化） |

### 3.3 用仿真交叉验证 fc（辅助电路 `c-0a8adca46f`）

单点仿真无法证明 fc，所以我另建了同拓扑、同 R/C、源频改为 **2 kHz** 的电路实测：

| f | 实测增益 | 理论 \|H\| | 偏差 |
|---|---|---|---|
| 2000 Hz | 0.712588（−2.943 dB） | 0.713855（−2.928 dB） | −0.178% |

2 kHz 处增益 0.7126 > 0.7071，说明 −3dB 点确实略高于 2 kHz，与解析值 2034 Hz 自洽（若 fc 真是 2000 Hz，
此处应恰好 0.7071）。这条独立数据点支持了第 3.1 节的定义和 2034 Hz 这个数。

## 11. 误差分析（区分设计偏差与仿真误差）

### 11.1 主表（1 kHz）

| 量 | 实际 | 理论 | 绝对误差 | 相对误差 |
|---|---|---|---|---|
| 增益 | 0.905646 | 0.906184 | −0.000538 | **−0.0594%** |
| 增益 (dB) | −0.8608 dB | −0.8557 dB | −0.0051 dB | — |
| 相位 | −34.2947° | −34.1922° | **−0.1025°** | −0.30% |
| 输出幅值（对实测输入归一） | 0.902741 V | 0.903278 V | −0.000537 V | −0.0594% |
| 输出幅值（对标称 1 V 源） | 0.902741 V | 0.906184 V | −0.003443 V | **−0.380%** |

### 11.2 两类误差必须分开看

**(A) 设计偏差** —— 元件取标准值 + 拓扑本身的 Q 上限导致的、与仿真器无关的偏差：

- fc：2000 → 2034.3 Hz，**+1.71%**。根源是 C1 用了 47 nF（理想需 47.9 nF，−1.88%），fc ∝ 1/C。
- 通带 −0.856 dB 的下垂：无源两级 RC 的 Q=0.476 < 0.707，是**结构决定**的，不是仿真错。

**(B) 仿真误差** —— 归一化后剩下的残差，才是仿真器/后处理带来的：

- 增益 **−0.0594%**（1 kHz）、**−0.178%**（2 kHz）
- 相位 **−0.1025°**（1 kHz）、**−0.1576°**（2 kHz）

这个量级（<0.2%）与 5 µs 步长（每周期 200 点）、梯形积分、以及正弦拟合的窗口截断相符，属于正常数值误差，
没有出现"仿真跑飞"或"拓扑被误解"的迹象。2 kHz 处残差略大也符合预期（步长相对周期更粗、相位变化更快）。

**(C) 一个需要单独交代的系统性偏差：源幅值**

所有仿真里输入通道实测幅值都是 **0.99679 V**，而不是设定的 1.000 V（**−0.321%**），两个频率下几乎完全相同
（1 kHz: 0.996793；2 kHz: 0.996787）。因为它在不同频率下高度重复，这不是随机误差，也不是我的拟合问题
（`min/max` 也是 ±0.997548，与拟合值自洽），而是**源模型/仿真器给出的实际激励幅度**与标称值的固定偏差。

它的后果：如果拿"标称 1 V"当分母，输出幅值误差被放大成 −0.380%；用实测输入归一后只剩 −0.0594%。
**−0.380% 里有 −0.321% 是激励偏差，不是滤波器误差**——这就是我在第 7 节坚持用比值增益的原因。

|---|---|---|---|

### 14.2 `tools/list` 的 description 够不够用

**基本够用，是我唯一的 API 文档，靠它一次就把电路搭对了**（8 个工具的 schema 全部读完才动手）。具体：

- 写得很到位的：`add_component` 明确说"不要传坐标、refdes 不传就自动编号"、`value` 的语义随元件类型变化并
  用 `value_name`/`value_unit` 回显（省掉了我猜"1.0 到底是峰值还是 RMS"的成本，实际回显 `amplitude/V` 就确认了是峰值）；

  （实测 21–24 s，估算准确）；`measure` 明确警告 `probe_id` 不是 Multisim 显示名"探针1"（这个提醒很有价值，

  （`AC_VOLTAGE` 另有 `aliases {"+":"1","-":"2"}`，电阻电容没有 aliases）。我先加了元件看 `pins` 再连线，
  所以没踩坑；如果直接照文档写 `["R1","+"]`，电阻上大概率会失败。

### 14.3 语义不清楚 / 后端与我的理解不一致的地方（4 处，都在多节点电路上）

**(1) `measure` 的 `gain` / `phase_deg` 按"探针添加顺序"配对，而不是按网络角色 —— 会把增益算反。**

主电路我先加 `P_out` 后加 `P_in`，返回：

```
"gain": 1.104183, "in_probe": "P_out", "out_probe": "P_in", "phase_deg": +34.2947
```

它把**输出**当成了输入，于是"增益"成了 1.104（= 1/0.9056），相位符号也反了。这个字段看起来权威
（`mode: "ratio"`、还带 `in_probe`/`out_probe` 标注），如果不核对就会直接写进报告，得出"增益 1.10、相位 +34°"的
错误结论。我在辅助电路里做了对照实验：把 `P_in` 先加、`P_out` 后加，同样的电路得到
`gain 0.71259, in_probe P_in, out_probe P_out, phase −62.458°` —— 完全正确。
**结论：`in_probe`/`out_probe` 完全由插入顺序决定，与哪条网络是 `in`/`out` 无关；而 `topology` 里明明已经有
`in_net`/`out_net`，这两套信息没有打通。** 建议按 `topology.out_net` 自动选输出探针。
我的做法：不信任 `gain`/`phase_deg`，只用每通道的 `amp`/`phase_deg` 自己相除相减。

**(2) `simulate` 的 `start` 被静默忽略。**

传 `start=0.002, stop=0.008`，返回 `t_range = [0.0, 0.007995]`、`stop: 0.008` —— `stop` 生效了，`start` 没有，
且没有任何 warning。对二阶这种有启动瞬态的网络，这会让拟合窗口混进瞬态（我实测影响幅值 0.20%）。
如果这是有意设计（总是从 0 开始、由调用方自己截窗），至少应在返回值或 description 里说明；
现在是"传了不报错也不生效"，属于最容易误导人的一类静默行为。

**(3) `get_waveform` 的 `preview` 采样错位（数据本身没问题）。**

`max_points=8` 时返回 `t = [0, 0.001, 0.002, ..., 0.007]`，但 `v = [0, −0.508237318, −0.508237421, −0.508237421, ...]`
—— 时间在推进，电压却几乎不变（都等于 t≈1 ms 处的值）。真实 CSV 在 t=0.001 是 −0.508、t=0.002 应是 −0.902 附近，
显然 preview 的 `v` 没有跟着索引走。**我因此没有用 preview 做任何判断**，而是直接读了 `artifact` 指向的 CSV 全文
（1601 行，数据正常）。这是显示层 bug，不影响 `measure`/拟合结果，但会让只看 preview 的调用方误判"波形是常数"。

**(4) 多节点/多分支拓扑：这次后端和我的理解一致，但表达方式容易误读。**

后端把电路识别为 `kind: "ladder"`, `n_series: 2`, `n_shunt: 2`，`stages` 是：

```
[{in,   series R1, shunt null},
 {mid,  series R2, shunt C1},
 {out,  series null, shunt C2}]
```

**语义上是对的**（C1 挂在 R1 之后的 `mid` 上、C2 挂在 `out` 上，正是我的设计），但 `stages[i].shunt`
表示的是"第 i 个节点上的并联元件"，而 `stages[i].series` 表示"从第 i 个节点出发的串联元件"——
两者错开一位。第一眼看到 `stage 1 = {net: mid, series: R2, shunt: C1}` 很容易误读成"R2 和 C1 并联在 mid 上"。
我是靠 `stages` 里的 `net` 字段和 `nets` 列表逐引脚核对，才确认后端没有把 C1/C2 的位置搞反。
对**多分支**电路（`fork` / `parallel_shunt`）我没有测试，但 `simulate` 的 description 提到这两类会直接
`LAYOUT_UNSUPPORTED` 并给出 `context.reason` —— 也就是说后端对"理解不了"的拓扑会选择拒跑而不是硬猜，
这个设计是对的，比静默出错好得多。**真正需要小心的是它"能跑"的拓扑里，`stages` 的字段语义有没有被调用方误读。**

### 14.4 一次恢复过程（非 API 错误，但影响了我的操作方式）

| 现象 | 我的判断 | 处理 |
|---|---|---|
| 6 条 `call` 串成一条 shell 命令 → `sandbox-center cmd decisionRecord missing actual resource subject` | 本地沙箱拒绝复合命令，与 MCP 无关（stdout 里没有 `[agent-cli]` 日志，说明进程没起来） | 改为一条命令一次 `call`，之后 31 次调用全部正常 |

由于这次失败没有进入 `trace.jsonl`（`seq` 从 1 连续到 31 无缺号），可以确认它没有到达执行器。

## 15. 结论

- 用 **R1=1kΩ、R2=10kΩ、C1=47nF、C2=4.7nF 的无源两级 RC 梯形网络**实现了二阶低通：分母为
  `1 + 9.87e-5·s + 2.209e-9·s²`，双实极点 2471 Hz / 4640 Hz，高频 −40 dB/dec，二阶性成立。
- **fc = 2034.3 Hz**（−3dB 定义），相对 2 kHz 目标偏 **+1.71%**，来自标准值量化，未做任何参数修饰。
- 1 kHz 处：**实测输出 0.902741 V / 增益 0.905646 / 相位 −34.295°**；
  理论 **0.906184 V / 0.906184 / −34.192°**。
- 归一化后误差 **增益 −0.0594%、相位 −0.1025°**；2 kHz 交叉验证点误差 −0.178% / −0.158°。仿真可信。
- 报告的 −0.380%（对标称 1 V）里，−0.321% 是激励源自身的幅度偏差，−0.059% 才是滤波器+仿真的真实误差 ——
  这两者不应混为一谈。
- 接口层面：31 次调用 0 报错，description 足以一次搭对电路；但 `measure` 的增益配对、`simulate` 的 `start` 静默失效、
  `get_waveform` 的 preview 错位这三处，都会让"看起来成功"的结果带上错误数值，需要调用方自己复核。
