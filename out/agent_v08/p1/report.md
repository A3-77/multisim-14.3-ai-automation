## 1. 电路设计（拓扑与理由）

**拓扑**：最简一阶无源 RC 低通

```
V1(+) ── in ──[ R1 ]── out ──┬── Vout (探针 P_out)
                             │
                          [ C1 ]
                             │
V1(-) ───────────────────────┴── GND1   （网络 "0"）
```

- 输入节点 `in` = `V1.1` + `R1.1`，并放探针 `P_in`
- 输出节点 `out` = `R1.2` + `C1.1`，并放探针 `P_out`
- 地节点 `0` = `V1.2` + `C1.2` + `GND1.1`

**为什么这么选**

1. 题目要"一阶"，无源 RC 是最小实现：一个储能元件 → 单极点、-20 dB/dec、相位从 0° 单调趋于 -90°，不会有源/负载稳定性问题。
2. 输出取自电容两端（对地），即低通；若取自电阻两端就是高通，所以拓扑方向不能反。
3. 不用有源滤波：题目没有增益/陡度要求，无源 RC 少一个运放、少一路供电，仿真里也不会引入运放宏模型的偏置误差。
4. R 串在源与负载之间、C 并在输出对地，这个结构同时也给源提供了一个确定的 1 kΩ 阻抗，避免"源直挂电容"导致仿真初值奇异。

后端自己把它归类成 `topology.kind = "bypass"`（`n_series=1, n_shunt=1`，`supported=true`）——命名上叫 bypass 有点反直觉，但它认的电气结构正是"1 串 + 1 并"，所以能正常布局和仿真。

## 2. R / C 参数

| 元件 | 位号 | 取值 | 是否标准值 |
|---|---|---|---|
| 电阻 | R1 | **1 kΩ (1000 Ω)** | 是，E12/E24 首选值 |
| 电容 | C1 | **330 nF (3.3×10⁻⁷ F)** | 是，E12 值 |

选值理由：目标时间常数 τ = 1/(2π·500) = 318.31 µs。在 E12 组合里，1 kΩ × 330 nF = 330 µs 是最接近的标准搭配（偏差 -3.5%）；次优的 1 kΩ × 300 nF = 300 µs 会给 +6.0% 偏差，更差。理论上 1.6 kΩ + 200 nF = 320 µs 只有 -0.5% 偏差，但 200 nF 只落在 E24、且 200 nF 电容的现货/价格远不如 330 nF，所以选 E12 的 1 k/330 nF。
另外 1 kΩ 让节点阻抗不至于过高（避免漏电/寄生影响），330 nF 又不需要用电解电容（电解容差 ±20% 会直接毁掉截止频率精度）。

**没有为了凑结果改过任何参数**：上面的 1 kΩ / 330 nF 就是建电路时一次性填进去的值，仿真返回的 `rlc_reported_by_multisim` 也确认 Multisim 里读回的正是 `R1=1000.0`、`C1=3.3e-07`。

## 3. 实际截止频率（自己算）

```
fc = 1 / (2πRC) = 1 / (2π × 1000 × 3.3e-7) = 482.2877 Hz
```

相对 500 Hz 目标：**-17.71 Hz，-3.54%**。这是一阶 RC 的标准值取舍带来的"设计偏差"，不是仿真误差。

|H(jω)| = 1 / sqrt(1 + (f/fc)²) = 1 / sqrt(1 + (1000/482.2877)²)

Vout_theory = 1.000 V × 0.4344050 = 0.4344050 V

## 11. 误差（区分设计偏差与仿真误差）

### 11.1 仿真误差：实测 vs "按实际建出来的 R、C" 的理论值

| 量 | 实测 | 理论 | 绝对误差 | 相对误差 |
|---|---|---|---|---|
| 输出幅值（基波） | 0.4318827 V | 0.4344050 V | **-2.5224 mV** | **-0.581%** |
| 增益 | 0.4332721 | 0.4344050 | -1.1330e-3 | **-0.261%** |
| 相位 | -64.3247° | -64.2526° | -0.0722°（多滞后 0.072°） | -0.112% |
| 输出幅值（峰值口径） | 0.4330184 V | 0.4344050 V | -1.3867 mV | -0.319% |

误差分解（这部分必须说清楚，否则 -0.581% 会被误读成电路错）：

1. **输入通道本身少了 0.32%**：源设 1.000 V，导出波形基波只有 0.99679 V。仿真器内部自适应步长 → 固定 5 µs 网格的插值会让正弦峰值略被削平（峰值 0.99763 V，基波 0.99679 V，谐波分量只有 1e-7 量级，所以不是失真，就是插值/取值带来的幅度亏损）。
2. 因此**幅值的绝对误差 -0.581% 里，约 -0.32% 属于"激励幅度亏损"，只有约 -0.26% 属于传递函数本身**。用增益（幅值比）衡量就自动抵消了激励亏损，得到 **-0.261%**，这才是滤波器传递函数的真实仿真误差。
3. -0.26% 与 -0.07° 的量级符合 SPICE 类仿真器在 200 点/周期下的数值误差（梯形积分 + 插值），不是拓扑或参数错误。若把采样点加密到 1000 点/周期，这个偏差应该会进一步收敛（本次未做，不做无据推断）。

### 11.2 设计偏差：实际 fc 与 500 Hz 目标的差

把"理想 500 Hz 设计"（|H| = 1/√5 = 0.4472136，φ = -63.4349°）作为规格基准：

| 量 | 500 Hz 理想设计 | 本次 482.29 Hz 实际设计 | 偏差 |
|---|---|---|---|
| 截止频率 | 500 Hz | 482.2877 Hz | -3.54% |
| 1 kHz 处增益 | 0.4472136 | 0.4344050 | -2.864% |
| 1 kHz 处相位 | -63.4349° | -64.2526° | -0.818° |

### 11.3 总误差（实测 vs 500 Hz 规格）

- 增益：0.4332721 vs 0.4472136 → **-3.12%**
- 相位：-64.3247° vs -63.4349° → **-0.890°**

**结论**：总误差 -3.117% 中，-2.864% 来自"用了 E12 标准值导致 fc 偏低 3.54%"（设计偏差），-0.261% 来自仿真数值误差；(1-0.02864)×(1-0.00261)-1 = -3.117%，账能对上。

## 12. 仿真是否成功，以及我怎么确认它真的跑了

**成功。** 判据（不是只看 `ok: true`）：

1. `simulate` 返回 `status: "ok"`，并给出 `timing`：`layout_s 0.009 / compile_s 15.585 / run_s 4.444 / total_s 20.038`——15.6 s 编译 + 4.4 s 求解，符合"启 Multisim 真跑"的时间特征（纯查表/伪造不可能有这种分阶段耗时）。
2. 生成了 `.ms14`（`compile.bytes = 31784`）和波形 CSV，CSV 实际有 **2400 行、5 µs 等间隔、t ∈ [0, 0.011995]**，时间轴严格单调均匀（我逐点校验过）。
3. **Multisim 回读的元件值** `rlc_reported_by_multisim = {R1: 1000.0, C1: 3.3e-07}` 与我填的一致——说明值真的进了网表，不是只存在我的会话里。
4. 物理自洽性：输入实测周期 1.000000 ms（=1 kHz）、幅值 ≈1 V；输出滞后 ≈64.3°、增益 ≈0.433，与 RC 解析解吻合到 0.3% 以内。若电路没真跑（例如输出恒 0、或直接复制输入），这几项不可能同时成立。
5. 换窗口可重复：`s-e307dfaa97`（0–6 ms）与 `s-22aa89a47f`（0–12 ms）两次独立仿真给出的增益 0.4332875 / 0.4332721、相位 -64.3267° / -64.3247°，差异 <0.01%，说明结果是可复现的数值解，不是一次性噪声。

### B. `tools/list` 的 description 够不够用

**够用，能一次把电路搭对**（4 个元件 + 3 条网络 + 2 个探针，全部一次通过，没有靠试错）。特别是这几点写得很好：

- `add_component` 明确说了"不要传坐标、布局由 simulate 自动算"，省掉了最大的一个坑；
- 明确说 `parameters` 的键是语义名（`frequency`）而不是数字序号，且给了 `UNKNOWN_PARAMETER` 的行为；
- `add_probe` 明确禁止传元件位号（会 `AMBIGUOUS_TARGET`），并说明 probe_id 与 Multisim 显示名（探针1）/输出名（V(探针1)）不是一回事；
- `measure` / `get_waveform` 的 `channels` 都以 probe_id 为键、结构一致，能直接对照；
- `simulate` 提前声明了阻塞 ~30 s 和 `LAYOUT_UNSUPPORTED` 的几种 reason，让我一开始就把拓扑搭成"1 串 + 1 并"而不是 T 型/并联到地。

不足（都能绕过，但会花时间）：

1. **没列引脚名**。`pins`/`aliases` 只有在 `add_component` 的返回值里才出现（V1 是 1/2 且有 `+/-` 别名，R/C 只有 1/2，GND 只有 1）。搭电路前无法从 schema 知道，只能"先加再看"。
2. **`family` / `part` 两个必填字段在 description 里用 `RESISTOR/RESISTOR_VIRTUAL` 这种斜杠写法列举**，初读容易误以为是一个字段。实际必须拆成 `family="RESISTOR"`, `part="RESISTOR_VIRTUAL"`。
3. **`connect` 的网络命名规则没写全**：只说"含地自动叫 0、含电源正极自动叫 in、其余 n1/n2"，但没说显式给 `net` 时是"新建"还是"追加到同名网络"（返回值里 `created` 字段暗示是后者）。我全部显式命名（in/out/0）来规避这个不确定性。
4. 返回的产物路径是相对仓库根的 `out\mcp\...`，不是相对我的 workdir，第一次看到会短暂困惑。

### C. 语义上我觉得不清楚的地方（重点两条）

1. **`simulate.start` 的实际语义**。文档说"起始时间 s（仅 transient）"，但实测 `start=0.002, stop=0.006` 导出的 CSV 是 `t ∈ [0, 0.005995]`、`n = 1200 = stop×fs`——`start` 对导出时间轴没有任何影响（既没裁剪，也没平移）。它到底是被忽略了、还是只影响内部求解起点？文档没说。这直接影响"能不能靠 start 跳过启动暂态"，我最后只能靠"拉长 stop + 自己截窗"来保证。
2. **`measure.mean` 与 `measure.offset` 并存且数值不同**。同一次测量里 P_out 的 `mean = 0.0108203`（全窗算术平均，含启动暂态）而 `offset = -1.3368e-06`（正弦拟合的直流分量）。两个字段都叫"直流/平均"的语义，差 4 个数量级，很容易被误当成"电路有 10.8 mV 直流失调"。建议明确标注 `mean` 是"全窗算术平均（含暂态）"。
3. 次要：RC 低通被 `topology.kind` 判成 `"bypass"`，这个词在电路语境里通常指"旁路/短路掉"，用在这里指"串一个、并一个到地"，读起来别扭（但 `supported=true`，功能正确）。
